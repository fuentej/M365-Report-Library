# Candidate: identity posture

Status: sources verified against Microsoft Learn; nothing built. Written for BRO-315 so the build issue can
be written without guessing. Nothing here was run against a tenant.

Cloud names follow the library: `Commercial`, `GCC`, `GCCHigh` (`-Environment`). Graph uses
`https://graph.microsoft.com` for Commercial and GCC and `Connect-MgGraph -Environment USGov` for GCC High
([national cloud deployments](https://learn.microsoft.com/graph/deployments)). Every Graph page cited below
carries a national-cloud table; "US Government L4" is the GCC High column, and GCC calls the global endpoint.

## How to read the table

* `Available` / `NotAvailable` appear only where a Microsoft page says so; the link is in the cell.
* `UNVERIFIED` means no Microsoft page found says either way. The collector should ask for the data and
  record a refusal in `run.log`, as the existing reports do.
* Source 1 reuses `Invoke-EntraUserCollector` in `shared/M365ReportLibrary.psm1`; it is not re-specified.
  That collector writes `users.csv` (`RunDate`, `Id`, `DisplayName`, `UserPrincipalName`, `Mail`, `UserType`,
  `AccountEnabled`, `CreatedDateTime`, `Department`, `JobTitle`, `City`, `Country`, `ManagerId`,
  `ManagerUserPrincipalName`) and does **not** collect `signInActivity`, so stale and never-signed-in
  accounts need source 5.
* All Graph sources below are read through the `Microsoft.Graph` PowerShell SDK or REST with the permissions
  named. The shared sign-in already requests `User.Read.All`, `Directory.Read.All`, `GroupMember.Read.All`
  and `AuditLog.Read.All`. `Directory.Read.All` satisfies list role assignments, and `AuditLog.Read.All`
  satisfies sign-in activity. The build still has to add `Policy.Read.All` (or `Policy.Read.ConditionalAccess`),
  `RoleAssignmentSchedule.Read.Directory`, `RoleEligibilitySchedule.Read.Directory` and
  `IdentityRiskyUser.Read.All`, which are not in that list.

Consolidated notes:

* License failures must show "not licensed" instead of zero. Source 2, source 5 and source 6 need Entra ID
  P1 or P2. Source 3 needs Entra ID P1 (Business Premium also covers Conditional Access); its risk-based
  policies need P2. Sources 4a and 4b need Entra ID P2 or Entra ID Governance. Source 7 needs P2, not P1.
* A token that has only `AuditLog.Read.All` can intermittently return
  `Authentication_RequestFromNonPremiumTenantOrB2CTenant` because reading the tenant license needs
  `Directory.Read.All` when that fact is not cached
  ([troubleshooting](https://learn.microsoft.com/troubleshoot/entra/entra-id/users-groups-entra-apis/b2c-or-tenant-premium-license-sign-in-activities)).
* Source 6 and 6b retention is 30 days at best. Appending from the last exported timestamp on a daily run
  builds a longer history than the source retains, as the Activity Explorer collector does. Each page holds
  at most 1,000 sign-ins; stopping after the first page drops the rest.
* Source 5 holds at most 500 users per page when `signInActivity` is selected, and a `$filter` on
  `signInActivity` cannot be combined with another filterable property. `0001-01-01T00:00:00Z` and `""`
  are empty values, not sign-in times.
* Directory audit logs (`GET /auditLogs/directoryAudits`) are an event source for changes to roles and
  policies ([audit logs overview](https://learn.microsoft.com/graph/api/resources/azure-ad-auditlog-overview));
  they were not in the starting questions and were not researched further.
* Source 3 is a snapshot. `enabledForReportingButNotEnforced` is the report-only state. A Conditional Access
  change shows up as a difference between two runs, with no record of who made it.

## Open items for the build issue

* In GCC High, ask for `signInActivity` and record a refusal in `run.log` if the property is rejected.
  List users itself is available in US Government L4; the property is not stated there.
* Source 4d (`isPrivileged`) and source 6b (`signInEventTypes`) are beta. Beta is not supported for
  production applications. The build issue has to accept that, or drop privileged filtering and
  non-interactive legacy sign-ins.

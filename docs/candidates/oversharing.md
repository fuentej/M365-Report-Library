# Candidate: oversharing

Status: sources checked against Microsoft Learn; nothing built. Written for BRO-359 so the build issue can be
written without guessing. Nothing here was run against a tenant.

Cloud names follow the library: `Commercial`, `GCC`, `GCCHigh` (`-Environment`). Graph uses
`https://graph.microsoft.com` for Commercial and GCC and `Connect-MgGraph -Environment USGov` for GCC High
(`https://graph.microsoft.us`) ([national cloud deployments](https://learn.microsoft.com/graph/deployments#microsoft-graph-and-graph-explorer-service-root-endpoints)).

## How to read the table

* `Available` / `NotAvailable` appear only where a Microsoft page says so; the link is in the cell.
* `UNVERIFIED` means no Microsoft page found says either way. The collector should ask for the data and
  record a refusal in `run.log`, as the existing reports do.
* **Role** is the least privileged permission or role a Microsoft page names for that call.
* Graph rows: the API pages list "US Government L4" as GCC High and the global service as Commercial and GCC.
  The library's rule is that GCC calls the global endpoint ([deployments](https://learn.microsoft.com/graph/deployments#microsoft-graph-and-graph-explorer-service-root-endpoints)).
* SharePoint Advanced Management (SAM) and Purview rows: the Learn pages found list **features**, not
  cmdlets. Where a cell rests on a feature row, it names the row and the cmdlet itself is not claimed.
* The cmdlets in rows 3 to 5 come from the SharePoint Online Management Shell. No page found says whether
  that module connects in GCC and GCC High, so connection is an open item below, not a table claim.

Consolidated notes:

* Rows 3a to 3e are Data access governance (DAG) reports. They are asynchronous: start, poll, export a CSV. The
  collector reads the CSV; it never reads the SharePoint admin center. The reports page lists a known issue:
  reports might not work when "Display concealed user, group, and site names in all reports" is cleared in the
  Microsoft 365 admin center, which only a Global Administrator can change
  ([limitations](https://learn.microsoft.com/sharepoint/data-access-governance-reports#limitations-or-known-issues)).
  The same page says the reports are unavailable for Microsoft 365 operated by 21Vianet.
* Rows 3c and 3d are windowed (28 days) rather than a stream. Append each export with the run date, as for a
  state source; a gap longer than 28 days between runs loses events, and the audit log (5a, 5b) is the longer
  record (180 days on Audit (Standard)). A `ReturnLargeSet` session that reaches 50,000 records is a failed
  window, not a complete export.
* Microsoft 365 E5 without SharePoint Advanced Management does not include the snapshot reports (3a, 3b, 3e).
  Activity reports (3c, 3d) are still available and return at most 10,000 sites
  ([reports](https://learn.microsoft.com/sharepoint/data-access-governance-reports)).
* Row 2 reads sharing links from the item. Learn does not list the creator on the permission, so "who created
  it" comes from the audit record (5a, 5b), joined on the object, not from row 2.
* Row 1 and row 2 together are the only fully API-level source here, and row 2 costs one call per item. Learn's
  [scan guidance](https://learn.microsoft.com/onedrive/developer/rest-api/concepts/scan-guidance) is the page to read
  before sizing it.

## Overlap

Compliance365 overlaps the item-level and site-level exposure pages (not read here); this report keeps to
read-only exports for a Power BI report. The Guest and external access report already covers guests, so
Specific-people links are shown only as a count by site and are not broken down by guest. The Purview information
protection report owns label coverage, so page 5 only joins a chosen label to site breadth and shows no coverage.

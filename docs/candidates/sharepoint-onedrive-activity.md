# Candidate: SharePoint and OneDrive usage and activity

Status: sources verified against Microsoft Learn; nothing built. Written for BRO-381 so the build issue can
be written without guessing. Nothing here was run against a tenant. Pages read 2026-10-10.

Cloud names follow the library: `Commercial`, `GCC`, `GCCHigh` (`-Environment`). Graph uses
`https://graph.microsoft.com` for Commercial and GCC and `Connect-MgGraph -Environment USGov` for GCC High
([national cloud deployments](https://learn.microsoft.com/graph/deployments), which gives
`https://graph.microsoft.us` as the GCC High root). Every Graph page cited below carries a national-cloud
table; "US Government L4" is the GCC High column, and GCC calls the global endpoint.

## How to read the table

* `Available` / `NotAvailable` appear only where a Microsoft page says so; the link is in the cell.
* `UNVERIFIED` means no Microsoft page read says either way. The collector should ask for the data and record
  a refusal in `run.log`, as the existing reports do.
* The Graph usage-report rows (1 to 7) reuse the evidence in [license-utilization.md](license-utilization.md)
  (sources 5d, 5e and 6). Each cell here was re-read on its own Learn page; none is copied unread.
* The shared sign-in requests `User.Read.All`, `Directory.Read.All`, `GroupMember.Read.All` and
  `AuditLog.Read.All`. The build still has to add `Reports.Read.All`, `ReportSettings.Read.All` and, for row
  11, `Sites.Read.All` and `Files.Read.All` as application permissions.
* **The headline finding:** every Graph usage report this report needs (rows 1 to 6) is marked `❌` for US
  Government L4, so it is `NotAvailable` through Graph in GCC High. The same reports are listed `Yes` for
  GCC-High in the Microsoft 365 admin center (row 8). So this report is a full report in Commercial and GCC,
  and in GCC High it is, by script, a site list, per-drive quota and audit-log event counts, with the usage
  reports reachable only by hand.

Consolidated notes:

* **GCC High.** Rows 1 to 6 return `NotAvailable` through Graph. Row 7 is UNVERIFIED because the pages
  disagree, so a run asks for it and records a refusal in `run.log`. Under the library rule ("a source not
  available in a cloud is skipped, and the README says why"), a GCC High run skips rows 1 to 6, writes rows 11
  and 12, and tries row 10. Row 8 shows the data exists in the admin center; turning that into a collector is
  an open item, not a claim. Microsoft Graph Data Connect "does not support any of the national cloud
  deployments" ([deployments](https://learn.microsoft.com/graph/deployments)), so it is not an alternative.
* **Usage reports are periods, not events.** Count columns aggregate 7, 30, 90 or 180 days. A daily run
  appends a snapshot stamped with the run date, and the `date` form gives one day. Reports typically become
  available within 24 to 72 hours and sometimes take several days
  ([usage reports overview](https://learn.microsoft.com/microsoft-365/admin/activity-reports/activity-reports)),
  so the newest days are missing, and a missing day is not zero activity. The overview says the last activity
  date in user, group, or site details is the most recent intentional activity "regardless of the selected time
  period", so rows 1 and 2 can show inactivity older than 180 days. The SharePoint activity and OneDrive
  activity pages instead say that date is for the selected date range, so rows 5 and 6 must not be read as
  lifetime last activity. The overview says a deleted user's usage data is removed within 30 days and the user leaves the User Details table, while chart totals still include them and a selected day still shows that day. The OneDrive usage page says deleted users continue to appear for 180 days. Do not drop OneDrive rows at 30 days, and do not keep every report for 180. Usage reports don't include perpetual license models (same overview).
* **Concealed names.** When `displayConcealedNames` is `true`, rows 1, 2, 5 and 6 hide site ids, site URLs and
  user principal names, so they cannot be joined to the site list (row 11) or the user list. Row 7 must be read
  first, and the report must show "names concealed, usage not joined" instead of zero-activity sites.
* **Site ids and URLs.** Site URL is missing when BYOK or Customer Lockbox is on, and the OneDrive URL "might
  not display". Resolving them needs `getAllSites` (row 11) with an application permission; the resolve page
  notes that `/sites?search=*` with delegated permissions "doesn't return all the sites".
* **Two definitions of "active".** Active files (rows 1, 2) count files saved, synced, modified or shared in
  the period. Last Activity Date (rows 1, 2) is driven by audit events, which for sites include page views.
  They answer different questions, and the page should label them.
* **Sharing counts are file counts.** Rows 5 and 6 count files shared internally or externally per user. They
  are not a link or permission inventory (see Overlap, oversharing).
* **Deleted sites and accounts.** Rows 1 and 2 carry `Is Deleted`, set after at least seven days. A row with
  `Is Deleted` true is not an inactive site.
